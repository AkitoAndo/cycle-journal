# X運用方針

- 更新日: 2026-09-13
- アカウント名: Hinaka
- 対象: X（旧Twitter）の立ち上げ・初期運用
- 状態: 初期方針。運用結果を見ながらHinakaと相談して更新する

## 目的

Hinakaという個人を主体に、ジャーナルや記録に関する情報を静かに共有する。
アプリの認知拡大だけを目的にせず、良質な記事や考え方との接点を少しずつ作る。

短期間で大量のフォローや投稿を行う運用は目指さない。
毎回の反応を見ながら、無理のない範囲で継続する。

## アカウントの立ち位置

Hinakaは、ジャーナルに関心があり、ジャーナルアプリを開発している個人として発信する。
アプリ公式アカウントのような見せ方はせず、アプリとの関係は隠さない。

| 項目 | 方針 |
|---|---|
| 表示名 | Hinaka |
| ユーザーID | Hinakaを含む候補から別途決定する |
| 主な話題 | ジャーナル、日記、記録、書く習慣 |
| アプリの扱い | Treowを開発していることをプロフィールに明記する |
| 発信の温度 | 短く、落ち着いた「です・ます調」で、宣伝を強くしない |

プロフィール文の初期案は次のとおり。

> ジャーナルや記録について、気になった記事と短いメモ。ジャーナルアプリ「Treow」を開発しています。更新のお知らせも少し。

## 発信する内容

### 良質な記事への反応

ジャーナル、日記、記録、書く習慣に関する記事を中心に扱う。
コメントを加える場合は、一つの投稿に一つの視点だけを添える。
抽象的にまとめすぎず、その投稿へ直接返すような短い言葉を使う。

記事をそのまま紹介したい場合は、通常のリポストを使う。
Hinakaの視点を加えられる場合は、引用リポストを使う。

反応文の例:

> 続けることより、戻りやすくするという視点が印象に残りました。

> 記録を読み返す時間まで含めて、書く習慣として考える視点がよかったです。

### リリースノート

Treowの更新時に、変更内容を短く伝える。
大きなプロダクトメッセージや開発思想は前面に出さず、ジャーナルアプリとして何が変わったかを中心に書く。

基本の形式:

> Treowを更新しました。
>
> - 変更した点
> - 修正した点
>
> ジャーナルを記録するときの小さな不便を減らす更新です。
> ［URL］

一つのリリースについて、同じ内容を繰り返し投稿しない。

### 返信

記事の著者や関連する投稿へ、短い感想や同意を返す。
相手から求められていない場面では、アプリのURLを返信に含めない。

## 発信しない内容

- Hinaka本人のジャーナル実体験
- 実際には経験していない利用談や感想
- 大きな開発思想や抽象的なプロダクトメッセージ
- 診断、治療、症状の改善を想起させるメンタルヘルス表現
- 過度な効果表現や、利用を急がせる表現
- 開発中の細かな変更をすべて知らせる投稿
- 第三者の悩みや体験を、集客のきっかけとして扱う返信

## 投稿量と交流

投稿数は目標ではなく、目安として扱う。

- 記事のリポストや短い反応: 週1〜3件程度
- リリースノート: 実際に利用者へ伝える更新があるときだけ
- 返信: 関連する投稿へ自然に返せるときだけ
- フォロー: 今後も読みたい相手に限定する

大量フォロー、短期間でのフォロー解除、無差別な返信、自動いいね、自動リポストは行わない。
運用量を増やす場合は、Hinakaと相談してから変更する。

## HinakaとCodexの進め方

方向性は、HinakaとCodexが壁打ちしながら決める。
Codexだけで大量の原稿や長期投稿計画を先に作らない。

1. Hinakaがテーマ、記事、更新内容のいずれかを共有する。
2. Codexが短い投稿案を最大3案まで作る。
3. Hinakaと表現や方向性を調整する。
4. textlintによる検査を行う。
5. Hinakaが確認した内容を公開する。

Codexが外部サービスへ投稿する場合は、その都度Hinakaから明示された依頼の範囲で行う。

引用リポストを検討する場合は、[引用リポスト100件の調査結果](./research/2026-09-13-quote-reposts-100-findings.md)を参照する。
実際の候補は、[引用リポスト記録テンプレート](./templates/quote-repost-record.md)を複製して記録する。

## textlint-jaの利用

外部へ発信する日本語のプロフィール、投稿、引用コメント、返信、リリースノートは、公開前にtextlintで検査する。
日本語ルールには、textlint-jaの一般文書向けプリセットである`textlint-rule-preset-japanese`を使用する。
技術文書向けの`textlint-rule-preset-ja-technical-writing`は使用しない。

このルールはXだけに限定しない。
App Storeの説明とリリースノート、Webサイトの公開文、公開ドキュメント、サポート文など、外部から見える日本語にも適用する。

原稿は`marketing/x/`配下のMarkdownファイルに置く。
リポジトリのルートから、次のコマンドを実行する。

```bash
npm --prefix docs run lint:text
```

特定のファイルだけを検査する場合は、次のように実行する。

```bash
npm --prefix docs run lint:text:external -- ../marketing/x/drafts/example.md
```

検査結果が0件になるまで修正と再検査を行う。
自動修正によって内容が変わる可能性もある。必要な場合だけ使用し、修正後に人が読み直す。
ルールを無効化する場合は、理由を明記してHinakaと相談する。

textlintは不自然な表記を見つけるための補助であり、内容の正しさや文脈は最終確認で判断する。

## 投稿前チェック

- Hinaka個人の発信として自然か
- Treowに触れる場合、開発者との関係が分かるか
- 実体験を装っていないか
- ジャーナルアプリとして簡潔に説明しているか
- メンタルヘルスの効果をうたっていないか
- 相手の投稿に宣伝を差し込んでいないか
- 投稿量を増やすこと自体が目的になっていないか
- textlintのエラーが0件になっているか
