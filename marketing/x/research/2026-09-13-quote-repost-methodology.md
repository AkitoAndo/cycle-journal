# 引用リポスト100件調査の方法

- 調査日: 2026-09-13
- 対象期間: 原則として2025-09-13から2026-09-13まで
- 対象言語: 日本語
- 目標件数: 重複を除いた100件

## 調査の目的

日記、ジャーナリング、手帳、ノート、学習記録の周辺で伸びた引用リポストを集める。
反応の大きさだけでなく、引用側が何を足したかを同じ項目で分類する。

最終的には、Hinakaが引用候補を選び、短い反応を作り、公開後に比較できる状態を目指す。

## 収集する分野

次の4区分から収集する。

1. ジャーナリング、日記、振り返り、書く習慣
2. 手帳、ノート、バレットジャーナル、手帳術
3. 勉強記録、読書記録、学習ノート、ログ
4. 作り手、版元、開発者による利用者への反応や続報

一つの区分だけに偏らないよう、各区分から20件以上を残す。

## 検索条件

Xの検索で、次の形を組み合わせる。

```text
ジャーナリング filter:quote min_faves:100 since:2025-09-13 until:2026-09-14
日記 filter:quote min_faves:100 since:2025-09-13 until:2026-09-14
手帳 filter:quote min_faves:100 since:2025-09-13 until:2026-09-14
ノート filter:quote min_faves:100 since:2025-09-13 until:2026-09-14
勉強記録 filter:quote min_faves:100 since:2025-09-13 until:2026-09-14
読書記録 filter:quote min_faves:100 since:2025-09-13 until:2026-09-14
バレットジャーナル filter:quote min_faves:100 since:2025-09-13 until:2026-09-14
「書く習慣」 filter:quote min_faves:100 since:2025-09-13 until:2026-09-14
```

作り手からの反応は母数が少ない。
必要な場合に限り、50いいね以上まで基準を下げる。
その場合は、数値の小ささを理由に除外せず、関係性の事例として扱う。

## 採用条件

次の条件をすべて満たす投稿を採用する。

- 引用リポストである
- 引用側の日本語本文を確認できる
- 日記、手帳、ノート、記録のいずれかと直接関係する
- 引用投稿のURLを確認できる
- 調査時点の反応数を確認できる
- 同じ投稿を重複して記録していない

## 除外条件

- 通常のリポスト
- 引用側に本文がない投稿
- 検索語だけが偶然含まれる無関係な投稿
- 同じステータスIDの重複
- 削除済みで、本文や反応数を確認できない投稿
- 日本語の反応を分析できない投稿

## 分類語

`primary_function`は、原則として次のいずれかへ寄せる。

- `short_reaction`: 驚きや共感だけを短く足す
- `specific_observation`: 画像や本文の具体的な一点を拾う
- `practical_addition`: 方法、形式、名称などを補足する
- `question_answer`: 元投稿の問いへ答える
- `self_followup`: 自分の投稿へ続報を足す
- `creator_response`: 作り手や版元として利用者へ返す
- `audience_translation`: 特定の読者へ読み替える
- `experience_endorsement`: 継続期間や経験から推薦する
- `strong_reframe`: 元投稿を強い主張や別の見方へ変える
- `resource_bridge`: 関連する記事や資料へつなぐ

一つの投稿に複数の役割がある場合も、中心となる役割を一つ選ぶ。

`quote_length_class`は、短い抜粋ではなく引用側の全文を基準にする。

- `short`: 40文字未満
- `medium`: 40文字以上140文字未満
- `long`: 140文字以上

`source_format_group`は、次の共通語を使う。

- `text`
- `article`
- `image`
- `video`
- `question`
- `use_report`
- `release_update`
- `other`

`relationship_group`は、次の共通語を使う。

- `self`
- `third_party`
- `creator_user`
- `publisher_user`
- `peer`
- `other`

## 数値の扱い

Xに表示された数字を、そのまま整数で記録する。
表示されない数字は0ではなく、`null`とする。

次の比率を分析に使う。

```text
いいね率 = いいね ÷ 表示
リポスト率 = リポスト ÷ 表示
保存率 = 保存 ÷ 表示
保存÷いいね = 保存 ÷ いいね
```

比率の分母が0または未取得の場合は計算しない。

## 100件の選び方

最初に、すでに詳しく確認した12件を基準事例として固定する。
新規収集した各区分から、いいね数の多い22件を選ぶ。

重複により100件へ届かない場合は、区分から外れた候補をいいね数の順に追加する。
100件を超えた候補は元データへ残し、分析対象からは外す。

この手順により、上位投稿だけへの偏りを抑えながら、各分野を同じ程度含める。

## 分析単位

次の単位で件数、中央値、比率を比較する。

- 主な役割
- 元投稿の形式
- 元投稿との関係
- Hinakaへの適合
- 短文、中程度、長文という文量
- 行動喚起の有無
- 根拠の種類

平均値は、一部の大規模投稿に引っ張られやすい。
中心的な比較には中央値を使う。

## 再現手順

1. 記載した検索条件でXを検索する。
2. 採用条件と除外条件を適用する。
3. 1件ずつJSON Lines形式で記録する。
4. ステータスIDで重複を除く。
5. 検証スクリプトを実行する。
6. 100件のCSVとJSON Linesを生成する。
7. 分類別の中央値を確認する。
8. Hinakaで採用する型を、数値と事例の両方から決める。

実行コマンドは次のとおり。

```bash
node marketing/x/research/scripts/build-quote-repost-dataset.mjs
```

## 限界

- フォロワー数の違いを完全には補正できない
- 元投稿の反応数をすべて同じ時点で取得できない
- Xの検索結果には表示順位の影響がある
- 反応数は調査後も変わる
- 引用文と結果の因果関係は断定できない

この調査は、伸びる文面を保証するものではない。
引用する理由を、観察可能な形で比較するための調査である。
