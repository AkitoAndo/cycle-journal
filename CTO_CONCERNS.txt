[D-01] タスクの振り返り項目がサーバーに同期されない（高）
--------------------------------------------------------------------------------
状態: 未対応
該当:
  - ios/Cycle/Features/Tasks/ViewModel/TaskViewModel.swift:458（pushUpsert）
  - ios/Cycle/Services/TaskService.swift:10-22（createTask / updateTask の引数）
内容: サーバーへ送っているのは title / description / status（完了状態）のみ。
      TaskItem の以下6項目は端末内 JSON にしか保存されない。
        intent（意図）/ achievementVision（完了イメージ）/ notes（注意点）
        fact（事実）/ insight（気づき）/ nextAction（次の一手）
      また TaskArchive（完了・見送り履歴）と TaskTemplate（テンプレート）も
      サーバー同期の仕組みがなく、端末ローカルのみ。
影響: 機種変更・アプリ再インストール・複数端末利用で、振り返り内容・履歴・
      テンプレートが失われる。振り返りはアプリの中核体験のため影響が大きい。
対応案: API の Task スキーマに6項目を追加し、create/update で送受信する。
      アーカイブ・テンプレートは API 追加 or タスクの状態（archived/skipped）
      としてサーバー側で表現する、のいずれかを検討。

[D-02] 「見送る」したタスクがサーバー上では未完了のまま残る（高）
--------------------------------------------------------------------------------
状態: 見送り機能の廃止で解消見込み（D-06 の移行で未完了タスクに戻るため、サーバーと一致する）
該当: ios/Cycle/Features/Tasks/ViewModel/TaskViewModel.swift:530（skipTask）
内容: skipTask はタスクを端末の一覧から外してアーカイブへ移すが、
      サーバーへは削除も状態変更も送らない（enqueueDelete / enqueueUpsert なし）。
      同じ端末では fetchServerTasks がアーカイブ済み serverId を除外するため
      再出現しないが、サーバー上は pending のまま。
影響: 同じアカウントの別端末・再インストール後に、見送ったタスクが
      未完了タスクとして復活する。resumeSkippedTask（再開）との整合も要確認。
対応案: 見送り時にサーバーへ状態を送る（例: status = "skipped" を API に追加、
      もしくは archiveTask と同様に delete を enqueue）。D-01 の方針と合わせて決める。
補足(2026-10-14): サーバーに残すのは意図的な設計の可能性あり
      （CycleTests の skipKeepsSyncedTaskOnServer が「delete を送らない」ことを検証している）。
      その場合も、別端末で未完了として復活する点の扱いは決めておきたい。

[D-03] 完了タスクのアーカイブ処理が保存失敗を検知しない（中）
--------------------------------------------------------------------------------
状態: 画面から呼ばれなくなった（2026-10-14 アーカイブ機能廃止）。関数は未使用のまま残存 → D-05
該当:
  - ios/Cycle/Features/Tasks/ViewModel/TaskViewModel.swift:505（archiveTask）
  - ios/Cycle/Features/Tasks/ViewModel/TaskViewModel.swift:613（archiveCompletedTasks）
内容: TaskArchiveStore.save / persist() の戻り値（@discardableResult）を見ずに、
      タスクを一覧から削除し、サーバーへ delete を enqueue している。
      一方、新しい skipTask / resumeSkippedTask は失敗時にロールバックして
      persistenceError を出す実装になっており、処理方針が不統一。
影響: ストレージ容量不足などで履歴の保存に失敗すると、完了タスクが
      端末・サーバーの両方から消え、復元できない。
対応案: skipTask と同じく「アーカイブ保存 → 成功時のみ一覧から除去・delete enqueue、
      失敗時はロールバック + reportPersistenceError()」に揃える。

[D-04] タスクの「表示する日付」に createdAt を使うが、サーバーに送っていない（中）
--------------------------------------------------------------------------------
状態: 端末側は解消（2026-10-15 scheduledDate 追加）。同期の課題は D-07 へ移管
該当:
  - ios/Cycle/Features/Tasks/ViewModel/TaskViewModel.swift（addTask(on:) / creationDate(on:)）
  - ios/Cycle/Features/Tasks/ViewModel/TaskViewModel.swift:pushUpsert / fetchServerTasks
内容: 2026-10-14 にタスクリストを日付管理に変更し、タスクは createdAt の日に表示する
      ようにした（見た目側の変更。保存形式は変更なし）。
      ＋ボタンで過去・未来の日を選んで追加すると、createdAt はその日の日時になる。
      しかし createTask は createdAt を送らず、サーバー側で作成時刻が付く。
      別端末で fetchServerTasks から新規取り込みすると、サーバーの createdAt が使われる。
影響: 過去・未来の日付に追加したタスクが、別端末・再インストール後には
      実際に作成した日に表示される（日付がずれる）。
対応案: API に「表示日（例: scheduledDate / taskDate）」を追加して送受信する。
      createdAt とは別の項目にする方が意味が明確。

[D-07] タスクの日付・締切（scheduledDate / deadline）がサーバーに同期されない（高）
--------------------------------------------------------------------------------
状態: 未対応
該当:
  - ios/Cycle/Features/Tasks/Model/Task.swift（scheduledDate / deadline を追加）
  - ios/Cycle/Features/Tasks/ViewModel/TaskViewModel.swift:pushUpsert / fetchServerTasks
  - ios/Cycle/Services/TaskService.swift
内容: 2026-10-15 にタスクへ「日付」「締切日時（空なら終日）」を追加した（オーナー要望）。
      端末内の JSON には保存されるが、API には送っていない。
      fetchServerTasks で別端末から取り込んだタスクは scheduledDate が空になり、
      作成日に表示され、締切も消える。
影響: 機種変更・再インストール・複数端末で、タスクの日付と締切が失われる。
対応案: API の Task スキーマに scheduledDate（日付）と deadline（日時・nullable）を
      追加し、create / update / 一覧取得で送受信する。D-01 と同じ対応でまとめられる。
補足: D-04（createdAt を表示日に流用していた件）は、この変更で端末側は解消
      （新規タスクは scheduledDate を使い、createdAt は本当の作成日時に戻した）。
      サーバー同期の課題は D-07 に一本化。

[D-05] 旧アーカイブ関連の関数・データが未使用のまま残っている（低）
--------------------------------------------------------------------------------
状態: 未対応
該当:
  - TaskViewModel.archiveTask / archiveCompletedTasks（画面から呼ばれなくなった）
  - TaskArchive.completedTasks（新規には増えない。既存データは作成日の一覧に表示中）
内容: アーカイブ機能の廃止は画面側のみで行い、データとロジックは残した。
      見送ったタスク（skippedTasks）は引き続き task_archives.json に保存している。
影響: 現状の動作に問題はないが、未使用コードが残る。CycleTests の archiveCompletedTask /
      archiveRejectsIncompleteTask は未使用関数をテストしている。
対応案: 既存の completedTasks を通常の tasks へ移す移行処理を入れた上で、
      archiveTask / archiveCompletedTasks と関連テストを削除する。
      ファイル名（task_archives.json）や型名も「見送り」用として整理する。

[D-06] 見送り機能の廃止に伴う、既存データの移行処理（要レビュー・中）
--------------------------------------------------------------------------------
状態: 実装済み・CTO レビュー待ち（feature/remove-task-skip）
該当: ios/Cycle/Features/Tasks/ViewModel/TaskViewModel.swift
      （loadArchives → migrateSkippedTasksToIncomplete / notesAppendingSkipReason）
内容: オーナー判断で「見送る」機能を削除した。1.0.11 で見送ったタスクが端末に残って
      いる場合、読み込み時に以下を行う（保存データを書き換える一度きりの移行）。
        - task_archives.json の skippedTasks を、tasks.json の未完了タスクへ戻す
          （createdAt・serverId はそのまま。sortOrder は末尾に採番）。
        - 見送り理由は notes（注意点）の末尾に「見送り理由: …」として追記。
        - 既に tasks 側に同じ ID がある場合は重複させずに見送り側を捨てる。
        - 戻したタスクは upsert を Outbox に積む（notes は D-01 のとおり未同期）。
        - 保存に失敗したら何も変えず、次回読み込み時に再試行。
      テスト: CycleTests の legacySkippedTasksMigrateBackToIncomplete ほか2件。
レビューしてほしい点:
  - 理由を notes に入れる方針でよいか（別項目を用意する案もある）。
  - SkippedTaskArchiveItem / TaskArchive.skippedTasks、updateArchivedTask・
    deleteArchivedTask の skippedTasks 分岐、DataExportService の「見送り」列は
    デコード互換のため残している。移行が行き渡った後に削除してよいか。
  - D-02 はこの移行で解消（見送り中のタスクが別端末で復活する問題がなくなる）。

[D-08] 週のふりかえり（U-03）で必要になるデータの送信・保存（要設計・中）
--------------------------------------------------------------------------------
状態: 未対応（設計段階。docs/backlog/ux/U-03-weekly-cycle.md）
該当:
  - ios/Cycle/Services/APIModels.swift（CoachRequest.diaryContent は日記1件分）
  - ios/Cycle/Features/Tasks/Model/Task.swift（セッションとのつながりを持つ欄がない）
  - ios/Cycle/Features/Coach/Models/ActionTask.swift（sourceSessionId はあるが未使用）
内容: 2026-10-23 にオーナーが「1週間のふりかえりサイクル」の方針を決めた。
      データ・コード側で次の設計が必要になる。
        1. 週のふりかえりで、その週の日記（本人が選んだもの）・セッションの
           テーマと気づき・完了したタスクのひとことを、まとめてコーチに送る。
           日記は端末にしか保存されていない（J-06 未着手）ため、端末から送る。
        2. 送った日記の本文をサーバー（Firestore のメッセージ等）に保存するか、
           その場の生成にだけ使うか。
        3. タスクに「生まれたセッション」への参照（セッション ID）を持たせる。
           ActionTask の sourceSessionId を使うか、TaskItem に追加するか。
        4. 週のふりかえり自体の保存形式（週の開始日、今週の一文、来週の一歩）。
        5. タスクの気づきが未同期（D-01）のため、別端末では材料が欠ける。
影響: 決めずに実装すると、日記の本文が意図せずサーバーに残る、
      端末を変えると週のふりかえりの材料やつながりが消える、などが起きる。
対応案: 1 は日記を複数件渡せる API にする。2 はプライバシーポリシーの記載と
      合わせて決める（保存しない場合も、生成された一文・一歩は保存する）。
      3〜4 は D-01 / D-07 の API 拡張とまとめて設計する。
