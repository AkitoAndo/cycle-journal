# U-03: 1週間のふりかえりサイクル（日記・コーチ・タスクをつなぐ）

| 項目 | 内容 |
|------|------|
| ステータス | :memo: Refinement |
| カテゴリ | UX（日記・コーチ・タスクの横断） |
| 優先度 | P0 |
| 依存 | C-10（セッション設計：まとめ画面）, S-02（通知設定） |
| 関連 | C-07（文脈管理）, J-06（日記のサーバー同期）, T-02（ふりかえり入力） |
| ロードマップ | 11/10〜11/30「使い続けてもらうための改善」の中心 |

## 背景

Treow のコンセプトは「日記 → 対話 → 小さな行動 → ふりかえり → また日記」という循環だが、
今の画面では日記・コーチ・タスクが同じ重さで並んでいるだけで、つながりは
「日記から話す」の一方向しかない。そのため、それぞれ単体では「普通の日記アプリ」
「普通の ToDo アプリ」に見えてしまう。

2026年のゴール（12/31 に WAU 300人）は「毎週戻ってくる理由」で決まる。
そこで、1日単位ではなく **1週間の体験** を設計し、3つの機能をその中でつなぐ。

## ユーザーストーリー

> ユーザーとして、毎日がんばって書かなくても、週に一度立ち止まって
> 「今週の自分」をふりかえり、来週の小さな一歩を持ち帰りたい。

> ユーザーとして、コーチとの対話で見つけた一歩を、忘れずに実際にやってみたい。

## 全体方針

**毎日は小さく、週末は少しだけ深く。**

3つの機能の間を流れるものを **「気づき」と「一歩」** の2つに絞る。

| 機能 | 役割 | かける時間 |
|------|------|-----------|
| 日記 | 材料を残す | 毎日1分（書かない日があってよい） |
| コーチ | 材料から気づきと一歩をつくる | ときどき 5〜10分 |
| タスク | 一歩を実際にやってみる | — |
| 週のふりかえり | 1週間をまとめて、次の週に渡す | 週1回 10分 |

- 毎日続けることを求めない。週1回のふりかえりだけでも「使い続けている」状態にする。
- 書かなかった日を責めない（C-10「立ち止まる」の考え方を週単位にも広げる）。
- タスクは「コーチと決めた一歩」が中心になり、汎用の ToDo アプリとは比べられない立ち位置になる。

## ある人の1週間

| 曜日 | 起きること | つなぎ目 |
|------|-----------|---------|
| 月 | 夜、日記を1〜2行書く。ホームの上に先週の「今週の一文」が出ている | ④ 週 → 次の週 |
| 火 | もやっとした日記から「日記から話す」。対話の終わりに「次の行動へ進む」を選ぶと一歩が1つ決まり、「タスクに追加」で今日のタスクに入る | ① コーチ → タスク |
| 水 | その一歩を完了する。ふりかえりは1問だけ：「やってみて、どうだった？」 | ② タスク → 気づき |
| 木・金 | 書かない日もある。何も責められない | — |
| 日 | 夜に通知が1回だけ届き、週のふりかえりセッションが始まる。コーチが今週の日記・気づき・完了した一歩を材料に「今週、いちばん心に残ったことは？」と聞く。最後に「今週の一文」と「来週の一歩」を1つずつ決める | ③ 1週間 → まとめ |
| 次の月 | 今週の一文と来週の一歩が、週の始まりに戻ってくる | ④ 週 → 次の週 |

## 4つのつなぎ目

1. **コーチ → タスク**: セッションのまとめで決まった「次の一歩」を、ボタン1つでタスクに追加する。
2. **タスク → 気づき**: コーチから生まれたタスクを完了したら、1問だけ聞く。答えは「気づき」として残る。
3. **1週間 → まとめ**: 週のふりかえりセッションが、その週の日記・セッション・完了した一歩を集めて「今週の一文」にする。
4. **週 → 次の週**: 今週の一文と来週の一歩を、次の週の始まりにホームで見せる。

## 決定事項（2026-10-23 オーナー決定）

| # | 論点 | 決定 | 理由 |
|---|------|------|------|
| 1 | 一歩を自動でタスクにするか | **ボタンを押して追加する**（自動では追加しない） | 勝手にタスクが増えるのは「押しつけない」に反するため |
| 2 | 週のふりかえりの日時 | **初期値は日曜の夜。設定で曜日・時刻を変えられる** | 週末に立ち止まる習慣をつくりやすく、生活リズムの違いにも対応できるため |
| 3 | 週のふりかえりで日記の中身をコーチに渡すか | **渡す。ただし送る前に今週の日記の一覧を見せ、チェックを外したものは送らない**（初期値はすべてチェック） | 日記は端末の中にしか保存されていないため、何がサーバーへ送られるかを本人が選べるようにする |

## 実装単位

1 PR で完了させない。上から順に、それぞれ単体でリリースしても価値が出る単位に分ける。

### 1. セッションのまとめ → 一歩をタスクに追加

> **実装状況（2026-10-25）:** C-10 の AI によるまとめ生成を待たず、まず本人が書く形で実装した
> （PR: feature/session-closing）。対話の「終了」で「対話を終える」画面が開き、
> 「今回の気づき」「次の一歩」を本人の言葉で残す。どちらも空のまま終えられる。

- [x] 対話の終わりに「次の一歩」を残せる。「今日の一歩に追加」（初期値オン）で今日のタスクになる
- [x] 押すと、今日の日付のタスクとして追加される（タイトル = 一歩の文）
- [x] 追加したタスクには、生まれたセッションへのつながり（`sourceSessionId`）が残る
- [x] ホームと記録タブの一歩の行に「対話から」の印（葉）を出す
- [ ] 印をタップすると、元のセッションのまとめを見返せる
- [x] 二重に追加しない（追加はまとめ画面の1回だけ。セッションに `nextStepTaskId` を記録）
- [ ] 分岐（深める / 次の行動へ進む / 立ち止まる）と AI によるテーマ・気づきの提案（C-10）
- [ ] 気づき・次の一歩のサーバー保存（CTO_CONCERNS D-08 と合わせて）

### 2. タスク完了時のひとこと

今は完了時に「事後情報」シート（事実・気づき・次の一手の3項目）が出る
（マイページの「完了時に事後情報を記入」がオンのとき）。

- [ ] コーチから生まれたタスクを完了したときは、1問だけのシートにする：「やってみて、どうだった？」
- [ ] 答えは「気づき（insight）」として保存する
- [ ] 「くわしく書く」で、これまでの3項目の入力に切り替えられる
- [ ] スキップしても完了状態はそのまま（今と同じ）
- [ ] 通常のタスク（コーチから生まれていないもの）の完了時の動きは今のまま

### 3. 週のふりかえりセッション

> **実装状況（2026-10-23 入口のみ実装）:** ホームのカード → 材料を選ぶ画面 → コーチとの対話、までつながった。
> ホームの刷新（2026-10-23）で、入口は「今週の樹」カード（樹・1週間の帯・ふりかえりへのボタン）に統合した。
> 材料は今ある「日記から話す」と同じ欄（`diaryContent`）でコーチに渡している。
> セッションのテーマ・気づきは C-10 が未実装のため材料に入れていない。完了したタスクは「一歩」に限らず今週完了したもの全部を出している。

- [x] ホームに「今週のふりかえり」カードを出す（それ以外の日も週の中ならいつでも開始できる）
  - [x] ふりかえり日の当日は目立たせる
  - [ ] 翌日の朝まで目立たせる
- [x] 開始前に、今週の材料を一覧で見せる
  - [x] 今週の日記（チェックボックス付き。初期値はすべてチェック）
  - [ ] 今週のセッションのテーマと気づき（C-10 のまとめが前提）
  - [x] 今週完了したタスクとその気づき（「一歩」だけに絞るのは 1. の後）
- [x] チェックしたものだけをコーチに渡してセッションを始める
- [ ] コーチの最初の一言は、材料に触れながら「今週、いちばん心に残ったことは？」に近い問いにする（サーバー側のプロンプトが必要。今は日記として渡している）
- [x] 材料が何もない週でも始められる（コーチは材料なしで問いかける。新しく入った人もここで使える）
- [x] 対話画面の最初の返答候補を週のふりかえり向けにする（「心に残っていることがある」「今週はちょっと疲れた」「うまくいったことがあった」「まだうまく言葉にならない」）
- [x] 終わりに「今週の一文」と「来週の一歩」を1つずつ決める（2026-10-25。対話の「終了」で
      「ふりかえりを終える」画面が開き、本人の言葉で書く。どちらも空のままでよい）
  - [x] 「来週の一歩」は決めなくてもよい（立ち止まる選択）
  - [x] 「来週の一歩」は「来週の一歩に追加」（初期値オン）で、来週の初日（月曜）のタスクになる
- [ ] 週のふりかえりは1週につき1つ。途中でやめても、その週のうちなら続きから再開できる
      （今は何度でも始められ、いちばん新しい一文・一歩が使われる。ホームの行は「もう一度ふりかえる」）
- [x] セッション履歴で、週のふりかえりは通常のセッションと見分けられる（「週のふりかえり」の印、一文を見出しに）

## 非対象

- 一歩の自動タスク化（決定事項 1）
- 1年のふりかえり（12月の集客施策で、同じ仕組みを年の単位に広げるかは別途決める）
- 樹のメタファーの可視化（今週の一文を「実」として見せる等）。論点4として別途検討する
- 連続記録（何週続いたか）の表示。罪悪感につながりやすいため、入れるなら別途検討する

## うまくいっているかの見方

ロードマップの計測（〜11/9 リリース予定）に、次のイベントを含める。

| 見たいこと | 数え方 |
|-----------|-------|
| 週のふりかえりが使われているか | 開始数・最後まで終えた数（週ごと） |
| 一歩が行動につながっているか | 「タスクに追加」を押した数、そのタスクが完了した数 |
| 通知が効いているか | 通知から開いた数、通知をオフにした数 |
| WAU への効果 | 週のふりかえりだけを使った人が WAU の何割を占めるか |

## 検討事項

- **週の区切り**: 週を「ふりかえり日の翌日 〜 ふりかえり日」と定義する案（日曜がふりかえり日なら月〜日）。ジャーナルのカレンダーは日曜始まりのため、表示との違いが気にならないか確認する。
- **ほかの通知との重なり**: 日記のリマインダー（毎日）やお試し期間の通知と同じ日・同じ時間帯に重ならないようにする。
- **サインイン**: コーチはサインインが必要。サインインしていない人には、ホームのカードでサインインを案内する。
- **コーチへの指示**: 週のふりかえり専用のプロンプトが必要（材料の扱い方、最初の問い、「今週の一文」の言葉の条件）。C-11 と合わせて作る。

## 技術メモ

- 「タスクに追加」: `TaskItem`（`ios/Cycle/Features/Tasks/Model/Task.swift`）にはセッションとのつながりを持つ欄がない。`ActionTask`（`ios/Cycle/Features/Coach/Models/ActionTask.swift`）には `sourceSessionId` があるが、今のタスクリストでは使われていない。
- 完了時のシート: `ios/Cycle/Features/Tasks/Views/TaskPostActionEntryView.swift`。表示の切り替えは `TaskListView` の `isPostActionPromptEnabled`。
- 通知: `ios/Cycle/Shared/Utilities/NotificationManager.swift` に毎日のリマインダー（`daily_reminder`）がある。週1回の通知は同じ仕組みで追加できる。
- 日記をコーチに渡す仕組み: `CoachRequest.diaryContent`（`ios/Cycle/Services/APIModels.swift`）は日記1件分。週のふりかえりでは複数件を渡す必要がある。
- タスクの「気づき」はサーバーに同期されていない（CTO_CONCERNS D-01）。週のふりかえりでは端末側から材料として送る。
- データの扱い（送信・保存）は CTO_CONCERNS D-08 に記録。
